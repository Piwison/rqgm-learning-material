# Judge prompt

**實際使用的 prompt 在 `eval/prompts/judge.md`。**

那裡是唯一的來源。**要改就改那個檔案**，不要在這裡另外抄一份 ——
兩份會漂移，而且你不會知道哪一份是真的在跑的。

## 為什麼它是獨立檔案而不是寫在程式碼裡

因為你會常常改它，而改它不應該需要碰 TypeScript。
Week 2 的 κ 校準有一半的工作是在改這份 prompt 和 rubric 的用字。

## 那份 prompt 裡每一條約束在防什麼

| 約束 | 防的偏誤 / 失敗模式 |
|---|---|
| 逐條獨立判定，不要先形成整體印象 | 月暈效應：一條的判定污染其他條 |
| 只根據輸入判斷，不要推測作者意圖 | 幻覺性判定 —— judge 自己腦補上下文 |
| **每一條都要附原文引用** | 校準不良。逼它停止憑感覺，也讓你可以抽查 |
| 不要獎勵長度 | 冗長偏誤 |
| 不要報告信心分數 | 校準不良。它說 95% 確定的時候實際可能 64% |
| 只輸出 JSON，不要前後綴 | 解析失敗會變成「猜一個判定」 |

## 改它的時候要注意

**改完要重跑全部案例，不能只跑失敗的那幾條。**

prompt 的改動是全域的 —— 你為了修 c2 而加的一句話，可能會讓 c4 的判定跟著變。
只重跑失敗案例會讓你看不到那個副作用。

## 溫度

`temperature: 0`。

同一條輸入跑兩次結果不同的話，你所有的數字都是雜訊。
如果 0 了還是不穩，問題不在溫度，在條目定義 —— 去看 `rubric-schema.md` 的第三種不一致。
