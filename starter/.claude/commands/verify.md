你剛才說某件事做好了。**現在證明它。**

## 規則

**「我讀過程式碼，看起來是對的」不算證明。** 那是你的意見。我要的是執行結果。

依照下面的階梯，**用得到最高的那一階**，並說明你為什麼只能到那一階：

| 階 | 證據 | 什麼時候只能到這裡 |
|---|---|---|
| **1** | 自動化測試通過，而且我**先看到它失敗過** | 有明確對錯的邏輯 |
| **2** | 真的執行了指令，貼出**完整輸出** | 腳本、CLI、資料轉換 |
| **3** | 真的打開了頁面，附**截圖**或 DOM 查詢結果 | UI 變更 |
| **4** | 查詢了真實資料，貼出**查詢與回傳** | 資料庫變更 |
| **5** | 只有型別檢查 / lint 通過 | **這一階不算證明。**只代表它能編譯 |

## 第 1 階有一個額外要求

**先讓測試失敗，再讓它通過。** 貼出兩次的輸出。

沒看過紅燈的綠燈不算數 —— 一個永遠通過的測試和沒有測試是同一件事，而你分辨不出來。

## 輸出格式

```
驗證方式：（一行）
證據階數：N，因為＿＿＿

--- 實際輸出 ---
（原封不動貼上，不要摘要、不要美化）

沒有被這次驗證涵蓋到的是：
-（誠實列出。「全部都涵蓋了」幾乎永遠是錯的）
```

## 三個不准

- **不准**貼你「預期會輸出」的東西。只貼真的跑出來的。
- **不准**因為輸出很長就摘要掉錯誤訊息。錯誤訊息是最有價值的部分。
- **不准**在失敗的時候改測試讓它過。**先告訴我它為什麼失敗。**
